# Double Pendulum

A numerical simulation of the double pendulum, implemented in **C++20** with **SFML 3** for real-time visualization, **CMake** for build configuration, and **Python** for data analysis.

The project combines classical mechanics, numerical integration, software testing, and scientific data analysis. Initial conditions can be specified from the command line or set interactively by dragging the pendulum masses.

## 1. Build, Execution and Data Analysis

### Requirements

* C++20-compatible compiler
* CMake 3.28 or newer
* Ninja
* SFML 3
* Python 3
* Python dependencies listed in `requirements.txt`

The test framework, doctest, is configured through CMake and fetched automatically when necessary.

### Clone the repository

```bash
git clone https://github.com/davidepatarchi/Double_Pendulum.git
cd Double_Pendulum
```

### Configure and compile

Configure the project using Ninja Multi-Config:

```bash
cmake -S . -B build -G "Ninja Multi-Config"
```

Build the simulation in Debug mode:

```bash
cmake --build build --config Debug --target progetto
```

Alternatively, compile an optimized Release build:

```bash
cmake --build build --config Release --target progetto
```

### Run the simulation

From the repository root:

```bash
./build/Debug/progetto
```

For a Release build:

```bash
./build/Release/progetto
```

The application opens an 800 × 800 window displaying the double pendulum.

#### Set the initial conditions

Initial angles can be supplied as command-line arguments, in degrees:

```bash
./build/Debug/progetto 120 33
```

The arguments specify the initial angles of the first and second pendulums, respectively.

Alternatively, drag the masses using the left mouse button to set the initial configuration and release the mouse button to start the evolution.

Press `Space` to reset the system to its equilibrium configuration.

### Data analysis with Python

The simulation records mechanical-energy data in `data/energy.csv`. The Python analysis script is located in `analysis/plot_energy.py`.

Create a virtual environment and install the dependencies:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

Run the analysis from the repository root:

```bash
python analysis/plot_energy.py
```

The script reads the CSV data and generates an energy plot for inspecting the numerical evolution of the system.

The CSV file is generated by the simulation. Run the simulation before performing the analysis if the required data are not available.

## 2. Physical Model and Numerical Method

### Physical system

The double pendulum consists of two point masses connected by rigid, massless rods, moving in a vertical plane under uniform gravitational acceleration.

The system is described by four dynamical variables:

$$
\mathbf{y} =
(\theta_1,\theta_2,\omega_1,\omega_2),
$$

where:

* \(\theta_1,\theta_2\) are the angular positions;
* \(\omega_1=\dot{\theta}_1\) and \(\omega_2=\dot{\theta}_2\) are the angular velocities;
* \(m_1,m_2\) are the masses;
* \(L_1,L_2\) are the rod lengths;
* \(g\) is the gravitational acceleration.

The angles are measured from the downward vertical direction.

The equations of motion are nonlinear and coupled: the angular acceleration of each pendulum depends on the configuration and motion of both masses.

### Cartesian coordinates

The positions of the masses are reconstructed from the angular coordinates.

Taking the fixed pivot as the origin,

$$
x_1=L_1\sin\theta_1,
\qquad
y_1=-L_1\cos\theta_1,
$$

$$
x_2=x_1+L_2\sin\theta_2,
$$

$$
y_2=y_1-L_2\cos\theta_2.
$$

These transformations connect the physical model to the graphical representation rendered with SFML.

### Equations of motion

The dynamics can be derived using Newton's laws or, equivalently, the Euler–Lagrange equations.

For generalized coordinates \(q_i=\theta_i\), the Lagrangian formulation gives

$$
\frac{d}{dt}
\left(\frac{\partial \mathcal L}
{\partial\dot q_i}\right)
-
\frac{\partial\mathcal L}{\partial q_i}=0,
$$

where

$$
\mathcal L=T-V
$$

is the Lagrangian, with \(T\) the kinetic energy and \(V\) the gravitational potential energy.

The resulting equations can be expressed as a first-order system:

$$
\dot{\mathbf y}=\mathbf f(\mathbf y).
$$

In particular,

$$
\dot\theta_1=\omega_1,
\qquad
\dot\theta_2=\omega_2,
$$

$$
\dot\omega_1=\alpha_1,
\qquad
\dot\omega_2=\alpha_2,
$$

where \(\alpha_1\) and \(\alpha_2\) are the coupled angular accelerations implemented by the simulation engine.

### Numerical integration

The continuous equations of motion must be integrated numerically to obtain the state at successive time steps.

The numerical integrator advances the state from \(t_n\) to \(t_{n+1}=t_n+\Delta t\). The choice of integration algorithm and time step affects the accuracy and long-term behaviour of the numerical solution.

The implementation of the integrator belongs to the simulation engine in `simulation/`.

For a conservative mechanical system, numerical integration should be assessed not only by the apparent smoothness of the animation but also by physical diagnostics, particularly the conservation of mechanical energy.

## 3. Energy Analysis

### Mechanical energy

The total mechanical energy is

$$
E=T+V,
$$

where \(T\) is the kinetic energy and \(V\) is the gravitational potential energy.

For the ideal double pendulum, the kinetic energy is

$$
\begin{aligned}
T={}&
\frac12 m_1L_1^2\omega_1^2
+\frac12 m_2L_2^2\omega_2^2\\
&+m_2L_1L_2\omega_1\omega_2
\cos(\theta_1-\theta_2).
\end{aligned}
$$

The third term is the coupling contribution. It arises because the motion of the second mass depends on the motion of the first.

Choosing the potential energy to vanish when both pendulums are in their lowest configuration gives

$$
V=(m_1+m_2)gL_1(1-\cos\theta_1)
+m_2gL_2(1-\cos\theta_2).
$$

Consequently,

$$
\boxed{E(t)=T(t)+V(t)}.
$$

For an ideal system without dissipative forces, the exact mechanical energy is conserved:

$$
E(t)=E(0).
$$

In a numerical simulation, deviations from this equality can reveal integration errors, finite-time-step effects, or inconsistencies in the implementation.

### Energy data

The simulation stores energy measurements in:

```text
data/energy.csv
```

The Python analysis script in `analysis/plot_energy.py` reads the recorded data and plots the energy evolution.

The analysis can be used to investigate:

* conservation of mechanical energy;
* numerical drift over time;
* the effect of the integration time step;
* the reliability of the numerical solution.

A useful diagnostic is the absolute energy deviation,

$$
\Delta E(t)=E(t)-E(0),
$$

or, when \(E(0)\ne0\), the relative energy error,

$$
\varepsilon_E(t)=
\frac{|E(t)-E(0)|}{|E(0)|}.
$$

Comparing these quantities across simulations with different time steps provides a more rigorous assessment of numerical accuracy than visual inspection alone.

## 4. Testing

The project includes an automated C++ test suite based on **doctest**. The tests are designed to validate the simulation engine independently of the graphical interface.

Build the application and tests:

```bash
cmake --build build --config Debug
```

Run the test suite through CTest:

```bash
ctest --test-dir build -C Debug --output-on-failure
```

To build only the test executable, when using the root build directory:

```bash
cmake --build build --config Debug --target pendulum_tests
```

The tests can be extended to cover:

* equations of motion and limiting cases;
* energy calculations and conservation;
* numerical integration accuracy;
* equilibrium configurations and symmetry;
* invalid inputs and numerical edge cases.

Passing tests helps establish the correctness of individual components, but it does not by itself guarantee the absence of every numerical or physical error.

The project is developed as an ongoing computational-physics project, with an emphasis on the connection between the physical model, numerical methods, software quality, and quantitative validation.
